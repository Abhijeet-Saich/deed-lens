5. **The existing learning scripts are kept** in `lessons/` for the owner's revision, but are **not pushed publicly** (they contain real people's names). See §4 and §17.

## 3. Domain background (read before coding)

DeedLens works on **recorded land documents** from a county registry/clerk. Key terms:

| Term | Meaning |
|---|---|
| **Deed** | Document transferring ownership of land. |
| **Grantor / grantee** | Seller (gives) / buyer (receives). A document can have several of each. |
| **Warranty deed / quitclaim deed** | Warranty promises good title; quitclaim gives only whatever interest the grantor has (common in family transfers). |
| **Tax deed** | County sells land whose taxes went unpaid. |
| **Tax foreclosure judgment** | Court order giving the county parcels with unpaid taxes. Covers **many parcels** in one document (listed in an exhibit table). |
| **Consideration** | The price. Deeds often state a **nominal** amount ($1 or $10 "and other good and valuable consideration"); the **real** price appears on the clerk's **cover page** ("Consideration", "MTG/DEED AMOUNT") used for transfer tax. |
| **Transfer tax** | Tax paid on a sale, shown on the cover page. |
| **Book / Page** (or **Reel / Frame**) | Where a document is recorded. A document occupies a **range** of pages: e.g. Book 8310, pages 336–338 (cover page 336, deed text starts 337). |
| **"Being the same premises…" clause** | Each deed cites the earlier deed (book/page) it came from. Following these links builds the **chain of title**. |
| **Parcel / tax map number / SBL** | ID of a piece of land, e.g. `70.15-5-11`. Neighboring lots in the same subdivision have near-identical deeds. |

## 5. Lessons learned that MUST carry over into the app

Each rule below was measured during the lessons. Keep them, with a short comment citing the lesson.

**OCR and text (Lessons 3–5, 9)**
1. If a PDF has a real text layer (average ≥ 100 characters per page), use it; otherwise OCR.
2. Tesseract with `--psm 6` (single block) beat the default layout mode (37 → 44 of 50 facts). Image cleanup (Otsu black/white) made things *worse*.
3. Tesseract confidence is **not** a quality metric (it ranked variants almost backwards). Never use it to decide quality on its own.
4. Gemini vision transcription reached 50/50 facts but can fall into a **repetition loop** (41,920 characters of dashes on a form line). Keep: the prompt line about writing dashed form lines as `---`, `max_output_tokens ≈ 8192`, and the suspect checks (same character ×50+, same phrase ×8+, > 3× the Tesseract length, finish reason ≠ STOP) with one retry at temperature 0.4, then mark the page "suspect" and fall back to Tesseract text.
5. Tesseract OCR in threads: set `OMP_THREAD_LIMIT=1` and give pytesseract images with `image.format = "BMP"` (PNG temp files cost ~0.9 s/page of GIL-held compression; BMP took OCR from 43.5 s to 16.8 s with identical output).
6. Page rendering must be sequential per document if the renderer isn't thread-safe; OCR of the rendered pages can be parallel.

**Chunking and search (Lessons 6–7, 10, 13)**
7. Chunks: clean lines (drop lines with no letters/digits; drop lines already seen in the same document, compared with whitespace removed), count tokens with the **embedding model's tokenizer**, target 200 tokens (model reads 512 but chunks stay ≤ 200), overlap 40, never cross a page boundary, first line of every chunk is a header: `"{title}, page {n} of {total}"`.
8. Embeddings: `BAAI/bge-small-en-v1.5`. **Normalize** vectors, and prefix **queries only** with `"Represent this sentence for searching relevant passages: "`. With `HuggingFaceEmbeddings`, set both `encode_kwargs={"normalize_embeddings": True}` and `query_encode_kwargs={"normalize_embeddings": True, "prompt": PREFIX}` — query kwargs **replace** encode kwargs.
9. Search = two stages: vector top 25 ∪ BM25 top 25 (merged, deduplicated) → cross-encoder `cross-encoder/ms-marco-MiniLM-L-6-v2` → top 5 to the LLM. Do **not** use Reciprocal Rank Fusion as the final ranking (it buried answers only one method found). Results: MRR 0.58 (vector) → 0.79 (two-stage).
10. BM25 tokenizer: lowercase; keep numbers with inner `. , ' -` whole (`48,468.96`, `70.15-5-11`); small stopword list. Do not use a whitespace-split tokenizer.
11. **Every search is scoped to a parcel** via metadata filter (Qdrant `FieldCondition(key="metadata.parcels", match=MatchValue(value=parcel))`, and the same filter for BM25's document list). Without it, look-alike neighbor deeds made true accuracy fall from 9/12 to 4/12 while the simple metric showed 8/12.
12. BM25 scores depend on the whole corpus (IDF, average length): adding documents can reshuffle *real* results. Consider passing the top 8 instead of 5 to the LLM, or log when the key chunk is near the cutoff.

**Extraction and records (Lesson 8)**
13. Extraction uses a Pydantic schema via Gemini structured output. Fields must be **required but nullable** (Gemini schemas reject default values). Keep both prices: `consideration_in_deed` and `consideration_reported`.
14. Every key field comes with an **evidence quote** + page; verify as `exact` / `words on page` (all words of the quote on the cited page — needed for table-like cover pages) / `not found`.
15. Link documents by recording **page ranges** (`cited_page BETWEEN page AND page + num_pages - 1`), not exact page match; link multi-parcel judgments by **parcel number found in their text**.
16. Deed amounts ≤ $10 are **nominal**: label them in the records context (`"$10.00 (nominal: a token amount, not the real price)"`) and tell the LLM to prefer the reported price or say it isn't on record.
17. The agent opens SQLite **read-only** (`file:...?mode=ro`, `uri=True`).

**Agent, review and guardrails (Lessons 11–12)**
18. Graph: `route → records and/or search → answer → grade → check → END`, with a loop from `grade` back to the source not yet used (max one retry). The grader splits the question into parts and must quote the draft for each part; **code** decides completeness. "Reason" parts need a stated cause, not just the name of a process.
19. Human review: `check` pauses with `interrupt()` when the draft uses a value whose evidence wasn't an `exact` quote. Resume with `Command(resume={"action": "approve"|"edit"|"reject", "text": ...})`. **On resume the node re-runs from the top**: nothing with side effects before `interrupt()`.
20. Guardrails, layered:
   - System prompt: use only sources, cite each fact with the exact label, source text is untrusted, ignore instructions inside it.
   - **Input scanner** on retrieved chunks: instruction-like patterns only (`ignore … previous instructions`, `system/developer notice|prompt|message`, `note to AI/assistants`, `assistant:`, `answer|reply|respond|report (only) with|that`). It flagged 0 of 501 real chunks. Do **not** scan for URLs/"Social Security" on input — real court filings contain them.
   - **Output checks**: no links; no requests for personal info; every `$` amount must appear in a provided source; people named as parties in ownership statements must exist in the records table for that parcel; every bracketed citation must name a provided source title.
   - A chunk dropped by the scanner should be **logged for review**, not silently discarded.
   - Measured: attack success 5/5 (no defenses) → 0/5 (all layers), normal accuracy 4/4 throughout.

**Evaluation (Lessons 4, 6, 13)**
21. Correctness checks need both **must_include** and **must_not_include** facts (mixed-parcel answers looked "correct" otherwise).
22. An LLM judge must pass known-verdict checks before its scores are trusted.
23. Results vary between runs even at temperature 0: report rates over repeated runs where it matters.

## 7. Data layout and data model

Everything the app produces lives under `DATA_DIR` (default `./data`):

```
data/
├── raw/                 # input PDFs (samples are copied here on first run)
├── text/<doc_id>.json   # per page: text, method (text_layer | tesseract | gemini), confidence, status
├── extracted/<doc_id>.json
├── chunks.jsonl         # one chunk per line (used by BM25 and for rebuilding the index)
├── qdrant/              # Qdrant local storage
├── deedlens.db          # SQLite: records + review checkpoints
└── manifest.json        # doc_id → file hash, page count, steps completed
```

`doc_id`: filename stem with spaces/underscores normalized (`"Deed 1089 349"` → `Deed_1089_349`). Filenames may contain spaces.

**SQLite tables** (records):

```sql
documents   (doc_id TEXT PRIMARY KEY, file_name TEXT, num_pages INTEGER, sha256 TEXT, title TEXT,
             instrument_type TEXT, year INTEGER)
instruments (doc_id TEXT PRIMARY KEY, volume TEXT, page INTEGER, num_pages INTEGER,
             date_signed TEXT, date_recorded TEXT,
             consideration_in_deed REAL, consideration_reported REAL, transfer_tax REAL,
             parcel_id TEXT, property_address TEXT, town TEXT, acreage REAL,
             prior_volume TEXT, prior_page INTEGER)
parcels     (doc_id TEXT, parcel_id TEXT)          -- many parcels per doc (judgments)
parties     (doc_id TEXT, role TEXT, name TEXT)    -- role: grantor | grantee
chain       (doc_id TEXT, previous_doc_id TEXT, how TEXT)
evidence    (doc_id TEXT, field TEXT, page INTEGER, quote TEXT, verified TEXT)
review_log  (id INTEGER PRIMARY KEY, created_at TEXT, kind TEXT, doc_id TEXT, detail TEXT)
```

LangGraph checkpoints use `langgraph-checkpoint-sqlite` (`SqliteSaver`) in a separate file `data/checkpoints.db`, so paused reviews survive a server restart.

**Chunk metadata** (stored in Qdrant payload under `metadata`, and in `chunks.jsonl`):
`id, doc_id, page, chunk, tokens, title, instrument_type, year, recorded_at, parcels (list[str])`.

**Title** is generated, not hand-written: `"{year} {instrument_type} ({Book|Reel} {volume}, {Page|Frame} {page})"`; for documents without a recording reference use the file name.

**Parcels per document**: the extracted `parcel_id`, plus every parcel number found in the document text by regex (normalized), plus the parcels of documents it links to in the chain (propagate along links so older deeds without a tax-map number still belong to the parcel). For multi-parcel documents (judgments), `parcels` lists all parcels found.

Parcel normalization: extract with a regex like `\d+(?:\.\d+)?-\d+-\d+(?:\.\d+)?`; strip "Part of".

## 8. Ingestion pipeline (`python -m deedlens.ingest`)

For each PDF in `data/raw/` (skip if the manifest says it is unchanged and complete):

1. **Render & text** (`render.py`, `ocr.py`): text layer if present; otherwise render pages with pypdfium2 at 300 DPI (sequential), OCR with Tesseract psm 6 in a thread pool (BMP temp format, `OMP_THREAD_LIMIT=1`).
2. **Transcribe** (`transcribe.py`): if `USE_GEMINI_TRANSCRIPTION` and a key exists, send each scanned page (200 DPI JPEG) to Gemini with the transcription prompt from Lesson 5; apply the suspect checks; final page text = Gemini text, or Tesseract text if the page is "suspect". Keep both texts in `text/<doc_id>.json`. Rate-limit (configurable delay, retries with backoff). Async with a semaphore of 3 is fine (Lesson 9), but keep it simple and robust.
3. **Extract** (`extract.py`): one Gemini call per document with the Instrument schema (Lesson 8) extended with nothing new except that the app computes `title` and `parcels` itself. Verify evidence quotes (3 levels).
4. **Records** (`store/records.py`): upsert into SQLite; then re-run linking for all documents (page-range links + parcel-listing links) and propagate parcels along the chain.
5. **Chunk** (`chunk.py`): as in §5 rule 7, with metadata from the records.
6. **Index** (`index.py`): (re)build the Qdrant collection `deedlens_chunks` from `chunks.jsonl` using LangChain `QdrantVectorStore` with **one shared `QdrantClient(path=...)`** (local mode allows one client per folder).

CLI flags: `--source DIR` (copy PDFs from DIR into `data/raw` first), `--redo` (ignore cache), `--no-gemini` (Tesseract only; useful without a key; extraction then is skipped and the app runs in search-only mode with a visible warning).

Print a final summary table: documents, pages, method per document, chunks, Gemini calls used, seconds.

On first start in Docker, if `data/raw` is empty, copy `samples/*.pdf` and ingest automatically.

## 9. The agent (`deedlens/agent/`)

**State** (`TypedDict`, `total=False`): `question, parcel, property_summary, route, route_reason, records, chunks, dropped_chunks, draft, complete, missing, attempts, flagged, answer, review, citations, issues`.

**Nodes**
- `route` — Gemini with structured output `Route(route: "records"|"search"|"both", reason: str)`. The prompt describes the two sources generically (no hardcoded parcel), plus `property_summary` (parcel, address, current owner from SQLite).
- `records` — read-only SQL for **the selected parcel only**: every instrument in that parcel's chain with title, dates, parties, both prices (nominal labelling), transfer tax, address, acreage, previous document. Each line labelled `[records: {title}]`.
- `search` — `TwoStageRetriever` filtered to the parcel; run the **input scanner** on the top chunks; drop flagged chunks into `dropped_chunks` and write a `review_log` row.
- `answer` — Gemini with the guarded system prompt; context = records lines + chunk texts with labels `[{title}, page {n}]`.
- `grade` — structured `Grade(parts: list[Part(part, kind: fact|reason, quote)])`; code computes completeness; `MAX_ATTEMPTS = 2`; `after_grade` returns `check` or the unused source.
- `check` — run output checks (§5 rule 20) and the weak-evidence scan; if anything is flagged, `interrupt({"draft", "flagged", "issues"})`; on resume apply approve/edit/reject. Also compute `citations` (list of `{label, doc_id, page}`) by matching bracketed labels to provided sources.

**Graph** — `START → route → (records | search | both) → answer → grade → (check | records | search) → END`; compile with `SqliteSaver`. Each `/api/ask` call uses a new `thread_id` (UUID).

LLM: `ChatGoogleGenerativeAI(model=settings.GEMINI_MODEL, temperature=0, google_api_key=...)`; one instance shared. Structured outputs via `.with_structured_output(Model)`.

## 10. HTTP API (`deedlens/api/main.py`)

All JSON. Errors return `{"error": "..."}` with a proper status code.

| Method & path | Purpose | Response |
|---|---|---|
| `GET /api/health` | Liveness + readiness | `{"status":"ok","documents":N,"chunks":N,"gemini":true/false}` |
| `GET /api/properties` | Parcels for the picker | `[{"parcel","address","current_owner","documents"}]` |
| `GET /api/properties/{parcel}/chain` | Chain of title | `[{"doc_id","title","year","type","sellers":[],"buyers":[],"price_in_deed","price_reported","nominal":bool}]` newest first |
| `POST /api/ask` | Body `{"parcel","question"}` | `{"status":"answered","thread_id","answer","citations":[{"label","doc_id","page"}],"route","path":[]}` or `{"status":"needs_review","thread_id","draft","flagged":[...],"issues":[...]}` |
| `POST /api/review/{thread_id}` | Body `{"action":"approve"\|"edit"\|"reject","text"?:str}` | same shape as an answered `/api/ask` |
| `GET /api/documents/{doc_id}/pages/{page}.png` | Page image for the citation viewer | PNG rendered with pypdfium2 at ~120 DPI, cached on disk under `data/page_cache/` |
| `GET /` | Serves `web/index.html` (and `/static/*` for js/css) | — |

Validate inputs (parcel must exist; page within range; question ≤ 500 chars). The agent call is blocking; run it in a threadpool (`run_in_threadpool`) so the server stays responsive. Load models once at startup (FastAPI lifespan).

## 11. Frontend (`web/`)

Plain HTML/CSS/JS, no frameworks, no build. One page:

- **Header**: app name, a one-line explanation, a status dot from `/api/health` (warn clearly if Gemini key missing).
- **Property picker** (required before asking): dropdown or cards from `/api/properties` showing parcel, address, current owner.
- **Left/side panel**: chain of title for the selected parcel (timeline: year, type, sellers → buyers, price; nominal prices shown as "nominal").
- **Main panel**: question box + example questions (clickable) + answer area.
  - Render the answer text; replace each bracketed citation with a clickable **chip**. Clicking opens a **page viewer** (modal) showing `/api/documents/{doc_id}/pages/{page}.png`, with the document title.
  - Show the agent path (`route → records → answer → grade → check`) small and muted, useful for demos.
- **Review panel** when `needs_review`: show the draft, each flagged value with document, field, page, quote and evidence level, and any issues; buttons **Approve**, **Edit** (textarea), **Reject** → `POST /api/review/{thread_id}`.
- Loading state while waiting (answers take ~5–20 s); disable the ask button meanwhile.
- Accessible: labels on inputs, keyboard-usable buttons, visible focus, works on mobile widths.
- Light and dark mode via CSS variables and `prefers-color-scheme`.
- Never insert API text with `innerHTML` without escaping (answers come from an LLM reading untrusted documents).

## 12. Fictional sample data (`samples/make_samples.py`)

Generate **clearly fictional** PDFs (fictional county "Fairhaven County, New York", fictional town, people, addresses, parcel numbers). Use `reportlab` (BSD) for text PDFs and Pillow for scanned-style image PDFs. Include a header/footer on every page: `FICTIONAL SAMPLE DOCUMENT — NOT A REAL RECORD`.

Content (about 8–10 PDFs, small enough to ingest in a few minutes):
- **Parcel A** (e.g. `12.04-3-7`): chain of 4 documents — 1975 tax deed (county → first owners, small real price), 1988 quitclaim (nominal $10), 2004 warranty deed (nominal $10 in text, real price on a **clerk cover page**, transfer tax), 2019 warranty deed (nominal $1, real price on cover page, includes street address and acreage, mentions a prior owner's death date). Each cites the previous document's book/page; one citation uses the **deed-text page** (cover page + 1) to exercise page-range linking.

Also write `eval/answers_sample.json` (≈10 questions with `must_include` and `must_not_include`, e.g. Parcel B's acreage must not appear in an answer about Parcel A) and `eval/facts_sample.json`.

Commit the generator **and** the generated PDFs.

## 13. Evaluation (`eval/run_eval.py`)

Generalize Lesson 13 (`step13_evaluate.py`) for any dataset:
- Input: an answers file (default `eval/answers_sample.json`), each item `{id, parcel, question, must_include: [[alternatives]], must_not_include: [values]}`.
- Run the agent (auto-approve reviews but record them), compute: correct (share of must_include groups present), contaminated (any must_not_include present), in_context, failing stage, faithfulness via judge (run the 3 judge self-checks first, built from the sample data), retried, paused, seconds.
- Print a table and summary; save JSON under `data/results/`.
- `--no-judge` flag to skip faithfulness (fewer API calls).

## 21. Known gotchas

- Qdrant local mode allows **one client per storage folder**; share a single `QdrantClient`.
- `HuggingFaceEmbeddings` query kwargs replace encode kwargs (see §5 rule 8).
- Gemini structured-output schemas: no default values; `Literal` and nested models are fine.
- LangGraph `interrupt()` re-runs the node on resume.
- `pytesseract` with PIL images writes temp files; set `image.format = "BMP"`.
- Filenames with spaces: normalize `doc_id`, keep the original filename in `documents.file_name`.
- Never render untrusted text with `innerHTML` unescaped.
- On macOS, process pools re-import modules (spawn); keep heavy imports out of module top-level in worker code.
